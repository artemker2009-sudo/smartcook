# Формат файла импорта каталога «Идеи»

Файл готовит директор, загружает администратор во вкладке «Каталог» (`/admin` →
Каталог → «Импорт JSON»). Приёмная сторона — `POST /api/admin/ideas`, операция
`import`.

**Главное правило: импорт НИКОГДА ничего не публикует.** Все рецепты
приезжают черновиками (`is_published = false`) и становятся видимыми только
после ручной вычитки и нажатия «Опубликовать» — по одному. Это то же правило,
что у «Кухонных заметок».

**Второе правило: импорт ничего не перезаписывает.** Рецепт с уже
существующим `slug` не обновляется и не дублируется — он **пропускается** и
попадает в отчёт со строкой «уже есть». Чтобы изменить существующий рецепт,
нужно править его в админке; молчаливая перезапись готового, вычитанного и,
возможно, уже опубликованного текста из случайно повторно залитого файла —
это потеря работы.

---

## Поля

### Обязательные

| Поле | Тип | Правила |
|---|---|---|
| `slug` | строка | Адрес рецепта `/ideas/<slug>`. Только латиница в нижнем регистре, цифры и дефисы: `^[a-z0-9]+(?:-[a-z0-9]+)*$`. 1–200 символов. Уникален в файле и в базе. **Задаётся вручную, сервер его не придумывает** — от slug зависит и адрес, и то, какой рецепт считается «уже существующим». |
| `title` | строка | 1–200 символов. |
| `description` | строка | 1–400 символов. Одно-два предложения: это подпись в карточке ленты и `og:description`, а не первый абзац рецепта. |
| `servings` | целое | 1–20. |
| `cooking_time_minutes` | целое | 1–1440. Общее время: подготовка + готовка. По нему работает фильтр «До 30 минут», поэтому число, а не строка. |
| `meals` | массив строк | От 1 до 4 значений **только** из: `завтрак`, `обед`, `ужин`, `перекус`. Повторы запрещены. Блюдо может подходить к нескольким приёмам пищи — сырники это и завтрак, и перекус. |
| `main_product` | строка | Ровно одно значение из: `курица`, `мясо`, `рыба`, `без мяса`. |
| `ingredients` | массив объектов | 1–40 штук. Каждый — `{ "name": "...", "amount": "..." }`. `name` обязателен, 1–100 символов. `amount` обязателен как поле, но может быть пустой строкой (например «по вкусу» лучше писать словами, чем оставлять пусто). Форма совпадает с `recipes.detailed_ingredients` — благодаря этому экран рецепта и режим «Готовим!» работают без переделки. |
| `steps` | массив строк | 1–40 шагов, каждый 1–600 символов. Один шаг — одно действие: в режиме «Готовим!» шаг читается вслух и занимает весь экран. |

### Необязательные

| Поле | Тип | По умолчанию | Правила |
|---|---|---|---|
| `cook_method` | строка или `null` | `null` | Одно из: `плита`, `духовка`, `без готовки`, `мультиварка`. В интерфейсе пока не показывается, но при вычитке проставить дешевле, чем возвращаться ко всем рецептам потом. |
| `tags` | массив строк | `[]` | До 12 штук, каждый 1–40 символов. Свободные слова — по ним собирается блок «Похожие идеи». |
| `allergens` | массив строк | `[]` | **Только** из словаря: `молоко`, `яйца`, `глютен`, `орехи`, `арахис`, `рыба`, `морепродукты`, `соя`, `кунжут`, `мёд`. Свободный текст запрещён. |
| `image_aspect` | строка | `square` | `square` или `portrait`. Определяет и пропорции генерируемой картинки, и высоту карточки в ленте. |
| `sort_weight` | целое | `0` | Больше — выше в ленте. Обычным рецептам оставлять `0`. |

### Чего в файле быть НЕ должно

Эти поля задаёт сервер, и присланные значения **игнорируются молча** (это не
ошибка импорта — просто выгрузка из другого места могла их принести):

`id`, `image_url`, `image_status`, `is_published`, `published_at`,
`created_at`, `updated_at`.

Любое **неизвестное** поле — тоже игнорируется, но попадает в отчёт
предупреждением: чаще всего это опечатка в названии нужного поля
(`meal` вместо `meals`), и её лучше увидеть.

## Правила проверки

**Размер.** Файл — не больше 1 МБ, не больше 100 рецептов за один импорт.
Больше — разбить на несколько файлов.

**Текст чистится, но не режется.** Из всех строк убираются управляющие
символы и схлопываются пробелы. А вот превышение длины — **ошибка, а не
обрезка**: молча укоротить вычитанный редактором текст хуже, чем сказать
«строка длиннее 400 символов, исправьте».

**Ошибка в одном рецепте не роняет весь файл.** Каждый рецепт проверяется
отдельно: годные добавляются, негодные попадают в отчёт с причиной. Так из
файла на 80 рецептов не приходится искать одну запятую вслепую.

**Дубли slug внутри файла.** Первый рецепт добавляется, второй и последующие
с тем же slug — пропускаются с причиной «дубль в файле».

**Дубли slug с базой.** Пропускаются с причиной «уже есть». Ничего не
перезаписывается.

## Отчёт после импорта

Админка показывает по итогам загрузки:

- **Добавлено: N** — список названий.
- **Пропущено: M** — построчно, `slug` + причина, одна из:
  - `уже есть` — рецепт с таким slug уже в каталоге;
  - `дубль в файле` — этот slug встречается в файле не первый раз;
  - `ошибка проверки: <что именно>` — например «meals: значение „полдник“ не из словаря», «description: 512 символов, максимум 400», «ingredients: элемент 3 без поля name».
- **Предупреждения** — неизвестные поля, если были.

Отчёт можно скопировать целиком — чтобы отправить директору на исправление
файла, не пересказывая руками.
