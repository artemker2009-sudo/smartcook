## 0. Суть

- **Подбор** = один запрос, где человек даёт НОВЫЙ ввод и ИИ подбирает рецепты:
  фото продуктов (photo-recipe / analyze) или текст — «что есть дома» и поиск с
  генерацией ИИ (search-recipe). НЕ считается подбором: открыть другое блюдо из
  той же тройки (/api/recipe), «другие блюда» по тем же продуктам (regenerate),
  рецепты из «Идей», список покупок, /api/ask, /api/daily.
  Пройди все AI-роуты и в отчёте дай таблицу: роут → считается / не считается.
- **Бесплатно: 3 подбора в неделю.** Неделя — с понедельника 00:00 по Москве.
  Число — настройка в админке (по умолчанию 3), не константа в коде.
- **Премиум** — подборы без недельного лимита. Общий защитный лимит
  (RATE_LIMIT_PER_HOUR / RATE_LIMIT_PER_DAY в lib/rateLimit.ts) остаётся для всех
  и НЕ ослабляется.
- **Тарифы** (цены только на сервере, клиенту не доверять).
  Обновлены 24.09.2026: тариф «Месяц» убран совсем, цены снижены.
  | id | название | цена | срок | подпись в карточке | бейдж |
  |---|---|---|---|---|---|
  | year | Год | 169 ₽ | 365 дней | Меньше 15 ₽ в месяц | — (выбран по умолчанию) |
  | forever | Навсегда | 490 ₽ | без срока | Один платёж — и всё | — |
  Покупка при активном Премиуме: новый срок = max(сейчас, текущий конец) + срок.
  `plan=month` больше не существует: checkout на него отвечает 400.
- **Оплата — Robokassa** (НЕ ЮKassa: она с 29.12.2025 не шлёт чеки самозанятых).
  СБП и карты. Чеки самозанятого — «Робочеки СМЗ» (Robokassa сама отправляет чек
  в «Мой налог» и покупателю). **Автоплатежей нет и не будет** — никаких рекуррентов.
- **Премиум привязан к аккаунту** (auth user). Гость, чтобы оплатить, сначала
  входит или регистрируется; после входа возвращается к оплате выбранного тарифа.
- Всё, что меняет поведение для пользователей, — за флагом **FEATURE_PREMIUM**
  (lib/features.ts). В проде он ВЫКЛЮЧЕН, пока Артём не включит сам. Для проверок
  на превью — включение через переменную окружения только для Preview.
  Страницы /premium и /oferta работают всегда (их проверяет Robokassa).

## 1. iPhone-приложение (Capacitor, среда "native-ios" из lib/installEnv.ts) — ЖЁСТКО

Правило Apple 3.1.1: в iOS-приложении нельзя кнопок, ссылок, цен и призывов,
ведущих к оплате не через Apple. Поэтому в среде native-ios:
- нет ссылок на /premium и /oferta (подвал, профиль, шторка — нигде);
- /premium и /oferta, открытые внутри iOS-приложения, → редирект на /;
- лимит подборов действует так же, но шторка при исчерпании — нейтральная:
  «Подборы на эту неделю закончились. Новые — в понедельник.» + кнопка «Понятно».
  Без слова «Премиум», без цен, без ссылок на сайт;
- если у человека Премиум (куплен на сайте) — он работает, в профиле видно
  «Премиум до …», но нет кнопок «Продлить» / «Оформить»;
- счётчик «осталось N подборов» показывать можно (это не призыв к оплате).
Ничего не прятать от проверяющих Apple «хитро» (по гео, по дате, по аккаунту) —
только правило «native-ios = без оплаты». Так же уже сделана кнопка CloudTips.

## 3. PR 2 — Премиум целиком (САМ ПРОВЕРИТЬ НА ПРЕВЬЮ, НЕ МЕРЖИТЬ — примет Артём)

Одна ветка, коммиты по частям. Всё за FEATURE_PREMIUM.

### 3.1 База (supabase_premium.sql в корне, как остальные миграции)
Только НОВЫЕ таблицы. Существующие таблицы и данные не менять.
- `premium_settings` — одна строка: free_podbors_per_week int default 3,
  updated_at. (НЕ в site_settings: там была публичная запись.)
- `podbor_usage` — id, user_id uuid null, session_id text null, kind text
  ('photo'|'text'), route text, created_at. Индексы под подсчёт за неделю.
- `premium_orders` — id bigint identity (это InvId для Robokassa), user_id uuid
  not null, plan text check in (month, year, forever), amount_rub numeric(10,2),
  status text check in (pending, paid, failed, refunded, expired), created_at,
  paid_at, premium_until_after timestamptz null, platform text,
  robokassa_payload jsonb (только поля ответа, без паролей и подписи).
- `user_premium` — user_id pk, premium_until timestamptz null, is_forever bool
  default false, updated_at.
- `premium_grants` — лог действий админа: id, user_id, action ('grant'|'revoke'),
  plan_or_months text, comment text null, admin_id uuid, created_at.
RLS включён на всех, политик для anon/authenticated НЕТ (как ai_rate_limit_events):
читает и пишет только сервер (service role) через API-роуты с проверенным
пользователем (getVerifiedUserId). У anon/authenticated снять все привилегии.
**Разрешение Артёма на сегодня:** эту миграцию (только CREATE новых таблиц,
индексов, политик, REVOKE и INSERT строки настроек) можешь применить сам через
Supabase MCP: сначала прогон в BEGIN … ROLLBACK, потом применить, потом проверить
pg_policies и привилегии обеих ролей рантаймом. Любой ALTER/DROP существующих
таблиц или изменение существующих данных — НЕ делать, описать в отчёте.

### 3.2 Лимит подборов
- Проверка на СЕРВЕРЕ в каждом роуте, который считается подбором, ДО вызова
  OpenAI: не Премиум и подборов за неделю >= настройки → ответ 402 с
  { code: "PODBOR_LIMIT", used, limit, resetsAt }.
- Запись в podbor_usage — только после успешного старта генерации. Если запись в
  podbor_usage упала — генерацию НЕ ломать (лог в console.error).
- Кто считается: залогиненный — по user_id; гость — по session_id.
- Флаг выключен → лимит не проверяется, но podbor_usage пишется (нужны данные).
- Демо-аккаунт App Review (AI_RATE_LIMIT_EXEMPT_USER_IDS) — без недельного лимита.

### 3.4 Оплата Robokassa
Сначала прочитай документацию docs.robokassa.ru: интерфейс оплаты, ResultURL,
SuccessURL/FailURL, фискализация (параметр Receipt) и «Робочеки СМЗ». Делай
строго по ней; всё, в чём не уверен, — в отчёт.
- POST /api/premium/checkout { plan } — только залогиненный (проверенный JWT).
  Создаёт premium_orders(pending) с ценой С СЕРВЕРА, возвращает URL оплаты:
  MerchantLogin, OutSum, InvId = id заказа, Description («Премиум SmartCook —
  1 год / навсегда»), Receipt (одна позиция с тем же названием, сумма,
  tax "none", payment_object "service", payment_method "full_payment"),
  SignatureValue, IsTest=1 когда ROBOKASSA_IS_TEST=true.
- POST /api/premium/robokassa/result — ResultURL. Без проверки Origin
  (isTrustedOrigin не применять — это сервер Robokassa), защита — подпись с
  Password #2. Проверить: подпись, заказ существует, сумма совпадает, статус
  pending. Идемпотентно: повторный вызов по оплаченному заказу не продлевает
  второй раз, но отвечает OK. Продлить user_premium по правилу сложения сроков.
  Ответ ровно `OK{InvId}`.
- /premium/success — НЕ выдаёт Премиум сам. Показывает «Проверяем оплату…»,
  опрашивает статус заказа (до ~30 секунд), затем «Готово! Премиум до …» и кнопку
  «Сделать подбор». Если за 30 с не пришло — «Оплата ещё обрабатывается, Премиум
  включится автоматически, обычно за минуту» + ссылка на профиль.
- /premium/fail — «Оплата не прошла. Деньги не списаны.» + «Попробовать ещё раз».
- Переменные окружения (только env, в код и отчёт — никаких значений):
  ROBOKASSA_MERCHANT_LOGIN, ROBOKASSA_PASSWORD_1, ROBOKASSA_PASSWORD_2,
  ROBOKASSA_IS_TEST, ROBOKASSA_HASH_ALGO (md5|sha256, по умолчанию md5).
  Нет ключей → checkout отвечает «Оплата заработает в ближайшие дни», без 500.
- Тесты: подпись (пример из документации), ResultURL — неверная подпись,
  чужая сумма, неизвестный InvId, повтор; сложение сроков; «Навсегда».
